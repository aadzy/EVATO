SCOSCA CoSiCoSt-alignment verification

Baseline = priority-route boost / actuation extension / fallback all disabled (old behavior). Tuned = all three fine-tuning features enabled. Same seed, same duration (600s), same network.

1. Priority route + priority-stage boost

Direction flips between "forward" and "reverse" as real-time congestion shifts across the district's corridor — proof the offset propagation order is demand-responsive, not the old static topological order.

Per-phase green-time allocation over time for a representative intersection. In the tuned run the phase aligned with the current priority route gets systematically more green than in the baseline.

2. Local Online Split Optimizer (gap-extension)

Baseline uses a rigid static program: realized phase durations should exactly match planned splits (flat/deterministic). Tuned uses SUMO's actuated program (min/max duration bound by actuation_extension_sec): realized durations vary step to step because green is extended when the stop-line is still occupied — direct evidence the gap-out mechanism is active.

3. DOS-driven cycle length

Cycle length still adapts to degree-of-saturation in both runs (steps 1-5/9 were already correct); shown here mainly to confirm the fine-tuning didn't regress this baseline behavior.
